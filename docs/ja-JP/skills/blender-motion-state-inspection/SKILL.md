# Blender Motion State Inspection（Blender モーション状態検査）

## 使用場面

- Blenderキャラクターのアニメーションにおいて、ねじれ、反転、潰れ、オフセット、または足の滑り（フットスライド）が発生しているとき。
- インポートされたアバター、アーマチュア、またはリターゲットされたモーションが期待されるポーズと一致しているか検証を求められたとき。
- レンダリング結果の見た目と、ボーン、バウンディングボックス、接地、向きベクトルなどの構造化されたファクトを比較する必要があるとき。
- モデルがキャラクター本体なのか、プロップ（小道具）、プロキシメッシュ、コントロールリグ、あるいは壊れたインポートなのかを判別する必要があるとき。

## コア原則

スクリーンショットだけでアニメーション3Dアセットを判断してはなりません。スクリーンショットは目視確認のエビデンスにはなりますが、座標軸の規約、ボーン名、オブジェクトスケール、ローカル変換、親子付けされたメッシュ、マテリアルスロット、およびフレームごとの接地状態を隠蔽してしまいます。

まずBlenderから構造化された状態を抽出し、そのファクトが意味する内容をビューポートのスクリーンショットやレンダリング画像で確認してください。

## 動作の仕組み

1. モーションを判断する前に、クリーンなシーンとアセットのベースラインを確立します。
2. エクスポーター、またはBlender内蔵のPythonインタープリターで実行されるBlender Pythonスクリプトを使用して、Blenderから構造化されたファクトを抽出します。
3. 接地、向き、スケール、およびリターゲティングのエラーが最も発生しやすいフレームをサンプリングします。
4. 測定されたファクトを、ユーザーの期待するポーズ、進行方向、接地平面、およびレンダリング目標と比較します。
5. 確認されたファクト、考えられる原因、および必要な修正を明確に分離した簡潔なレポートを作成します。

## 検査ワークフロー

1. **シーンのインベントリ作成**
   - メッシュ、アーマチュア、エンプティ、カメラ、ライト、モディファイア、親子関係、非表示オブジェクトを一覧化します。
   - アバターを評価する前に、キャラクターメッシュとヘルパー/プロキシジオメトリを分離します。
   - オブジェクト空間およびワールド空間のバウンディングボックスを記録します。

2. **スケルトン（骨格）の特定**
   - アーマチュア名、ポーズボーン、ボーンのヘッド/テール座標、ロール角、親チェイン、コンストレイント、レストポーズ軸を取得します。
   - 腰（hips）、背骨（spine）、首（neck）、頭（head）、肩（shoulders）、肘（elbows）、手（hands）、太もも（thighs）、膝（knees）、足首（ankles）、足（feet）などの意味的なボーンをマッピングします。
   - 左右ペアの欠落や特殊な命名規則にフラグを立てます。

3. **前方（Forward）、上方（Up）、側方（Side）軸の決定**
   - 骨盤、背骨、肩、腰、頭、足を組み合わせて判定し、単一のメッシュ法線に依存しないようにします。
   - ローカルアーマチュア軸をワールド軸およびインポートファイルの規約（glTFのY-up vs BlenderのZ-upなど）と比較します。
   - 顔/頭/足の向きがルートモーションと競合している場合、反転または逆向きインポートの疑いとしてマークします。

4. **アニメーションフレームのサンプリング**
   - 開始、中間、接地、空中、極値（extreme）のフレームを検査します。
   - ルート位置、ルート進行方向（heading）、骨盤の高さ、胴体の傾き、四肢の向き、足のクリアランス、メッシュの境界を記録します。
   - 長時間または高速なモーションの場合は、フリップ、着地、ターン、衝突、床への接触付近でより密にサンプリングします。

5. **リターゲティングを疑う前のモデル整合性チェック**
   - アニメーションを適用する前に、クリーンなベースライン形状を確認します。
   - ユーザーが明示的に修復を求めない限り、元のメッシュ、マテリアル、アーマチュア、スキニングを保持します。
   - 説明のつかない球状の塊、巨大なプロキシメッシュ、押しつぶされたボディは、原因が特定されるまでインポートまたは選択の問題として扱います。

6. **接地およびモーションの問題診断**
   - 床へのめり込み: フレームごとに足または靴の最下点頂点と床の高さを比較します。
   - 足の滑り（フットスライド）: 接地フレーム間での足のワールド座標を比較します。
   - 脚の交差（クロスオーバー）: 左右の太もも、膝、足首、足の横方向の順序関係を比較します。
   - ねじれ破損: 四肢の軸周囲のロール/ツイストとは別に、ボーンの回転方向を個別に比較します。
   - スケールドリフト: アニメーション時のメッシュ境界と、クリーンなベースライン境界を比較します。

7. **所見よりもファクトを優先して報告**
   - フレーム番号、オブジェクト名、ボーン名、ワールド座標、しきい値を含めます。
   - 確認された不具合と、視覚的な疑いとを区別します。
   - 構造化された状態によって何を見るべきかが説明された後にのみ、スクリーンショットを添付します。

## 具体例

### 足が滑る歩行サイクル

シナリオ: リターゲットされたキャラクターが歩行サイクル中に滑っているように見えるが、正面カメラのアングルでは足の接地が判断しにくい。

ワークフローの適用:
- シーンインベントリ: キャラクターメッシュ `HeroBody`、アーマチュア `HeroRig`、床平面 `Floor`、非表示プロキシメッシュなし。
- スケルトン特定: 意味的な足は `foot.L` と `foot.R`、腰は `pelvis`、ルートボーンは `root`。
- フレームサンプリング: 接地瞬間のフレーム 1, 18, 24, 30, 42, 48 を検査。
- 接地問題の診断: 接地フレーム中のワールド空間での足の位置を比較。

抽出されたファクト:

| フレーム | ファクト | エビデンス |
| --- | --- | --- |
| 18 | 左足が接地 | `foot.L min_z = 0.004`、つま先と踵の両方が床付近 |
| 24 | 接地中に左足が滑っている | 6フレーム間で `foot.L x = 0.21 -> 0.28` |
| 30 | 骨盤が前進し続けている | `pelvis y = 1.14 -> 1.31` |

判定: レンダリング準備状態としては Fail。モーションに対してフットロックのクリーンアップまたはリターゲティングコンストレイントの再確認が必要。ボディメッシュのプロポーション変更は不要。

### 逆向きにインポートされたキャラクター

シナリオ: キャラクターは静止フレームでは正しく見えるが、アニメーションさせると期待される移動方向と逆に動く。

ワークフローの適用:
- 軸の特定: 頭、胸、足、およびルートモーションを比較。
- フレームサンプリング: フレーム1と移動経路の中間点を検査。
- 事実の報告: ルート進行方向とモデルの対面方向を分けて記載。

抽出されたファクト:

| フレーム | ファクト | エビデンス |
| --- | --- | --- |
| 1 | キャラクターの顔がワールド `-Y` を向いている | `neck` から `head` へのベクトルが `-Y` |
| 72 | ルートモーションはワールド `+Y` へ進行 | `root y = 0.0 -> 2.8` |
| 72 | 足は進行方向と逆向き（見た目上）を向いたまま | 変位が `+Y` であるのに対し、つま先ボーンは `-Y` を向いている |

判定: インポート時の逆向き配置、またはリターゲティングの前方軸の不一致の可能性が高い。アニメーションカーブを編集する前に、インポート/リターゲットの軸マッピングを修正する。

## 実践的なしきい値

- シーン単位の設定がない限り、Blenderのデフォルトのメートル単位系を前提とします。
- 床が柔らかい、または意図的にデフォルメされている場合を除き、1〜2cmを超える床へのめり込みは目視可能な不具合として扱います。
- 5%を超える急激なスケール変化は、リグ、コンストレイント、またはトランスフォーム継承の問題の可能性が高いとして扱います。
- 空中での反転モーション中に左右の足首の順序が逆転する場合、後で復帰したとしても脚の交差リスクとして扱います。
- ソースモーションに急旋回が含まれていない限り、フレームあたり30度を超えるルート進行方向の急変は異常として扱います。

## アンチパターン

- タスクが明示的にメッシュ修復でない限り、ポーズを合わせるために身体のプロポーションを変更してはならない。
- 記録する前にクリーンなベースラインをベイクして消去してはならない。
- 単一のレンダリングカメラアングルをポーズが正しい証拠として使ってはならない。
- キャラクターの一部でない理由を記録する前にヘルパーオブジェクトを削除してはならない。
- 頭、足、胴体、およびルートモーションを総合的に確認せずに、アバターが+Y、-Y、+X、-Xのいずれを向いているかを推測してはならない。

## ツールに関する注意

Blender状態エクスポーターが利用可能な場合は、メッシュ、アーマチュア、ポーズボーン、マテリアル、接地、バウンディングボックス、およびサンプリングされたアニメーションフレームを含むJSONを優先します。エクスポーターが存在しない場合は、システムの通常のPythonインタープリターには `bpy` が含まれていないため、`blender --background scene.blend --python collect_motion_state.py` のようにBlender自身を介して軽量なBlender Pythonスクリプトを実行してください。
