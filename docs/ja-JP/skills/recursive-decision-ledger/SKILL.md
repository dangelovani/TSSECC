# 再帰的決定台帳 (Recursive Decision Ledger)

繰り返しのロールアウトや「Prime Gauss」形式の再帰的プロンプトによってより深い計算を行いたい場合に本スキルを使用します。反復試行、以前のメモリ、最新の情報、明示的な評価マークといった有益な部分は維持しつつ、「ループが確実性を証明していると思い込む」という安全でない誤解を排除します。

## 台帳規約 (Ledger Contract)

すべてのロールアウトで以下を記録します：

- ロールアウトIDとタイムスタンプ
- 過去に承認された最善候補（Prior accepted winner）および監視リスト（Watchlist）
- 新たに取り込まれた最新情報
- 探索空間の規模
- 使用したモデルファミリーまたはヒューリスティクス
- 試行回数および有効試行回数
- 上位候補一覧
- 決定評価マーク（判定）
- 過去の台帳との整合性マーク（Coherence marks）
- 採用（Promotion）ゲートの判定結果

追記専用の台帳にはJSONLを、人間向けの要約にはMarkdownを使用することを推奨します。

## ロールアウトループ

1. 過去の台帳を読み込む。
2. タイムステップ0時点で新しい情報を収集・確定する。
3. 有界な探索を実行する。
4. 各候補に評価マークを付与する: `accept`（採用）、`watch`（監視）、`reject`（却下）、`decay watch`（監視減衰）、または `needs replay`（リプレイ検証必要）。
5. 勝者候補を過去の勝者および直近の評価済みロールアウトと比較する。
6. ドリフト、テールリスク、データの陳腐化、リプレイ失敗によって過去の評価が無効化された場合は、候補をダウングレードする。
7. 要約を作成する前に、成果物を追記・保存する。

## 整合性マーク (Coherence Mark)

簡潔な整合性マークを出力に含めます：

```text
アンサンブルと過去の勝者の一致: true
再帰的推論と過去の勝者の一致: false
最新ロールアウトとの一致: true
本番採用（Live promotion）の許可: false
理由: リプレイ検証および鮮度ゲートを満たしていないため
```

## 採用ルール (Promotion Rules)

取引、資本配分、本番デプロイ、マイグレーション、破壊的運用において、再帰的試行による確信度は「人間の承認」の代わりにはなりません。

ユーザーが本番実行を明示的に承認し、かつリポジトリ/サービスのゲートがそれを許可している場合を除き、常にペーパーテスト、ドライラン、読み取り専用、プレビュー、またはステージングモードをデフォルトとします。

以下の条件がすべて満たされた場合にのみ採用します：

- 選択された評価指標において、候補が過去の承認済み勝者を上回っていること。
- 正当性テストおよびリプレイ検証を通過していること。
- リスク制限が明示されていること。
- エビデンスが永続化されていること。
- 必要に応じてユーザーから本番実行の承認を得ていること。

## サマリーの形式

過度な修飾を排し、結論から端的に記述します：

```text
ロールアウト 15 が完了しました。以前の勝者が引き続き最善を維持していますが、優位性は 17% 低下しました。
ステータス: 監視継続（本番未投入）。次のゲート: 板情報の鮮度がしきい値未満の状態での 20 回のリプレイ約定検証。
```
