# orch-change-feature

アクター・アクション・ターゲット: **orch · change · feature**。[`orch-pipeline`](../orch-pipeline/SKILL.md) の共有エンジン上の薄いラッパー。

## いつ使用するか

- 既存の機能が**動作している**が、望ましい動作が異なる場合（「変更」「調整」「〜もできるように」「XではなくYにする」）。
- 兄弟との区別：
  - **壊れていない** → `orch-fix-defect` ではない（再現すべきバグがない）。
  - **新しくない** → `orch-add-feature` ではない（機能は既に存在する）。

## 操作設定

- **デフォルトサイズ下限:** small — ほとんどの微調整は1〜2個の関数。
- **フェーズマスク:** 0 → （新しい動作に調査が必要な場合のみ1）→ 軽量2 → 4 → 5 → 6。
- **最初のアクション（フェーズ4）:** *既存の*テストを新しい望ましい動作を表現するよう更新し、パスするまで実装を変更。テストを先に変更するのが、微調整と修正を分けるポイント。

## 仕組み

1. 上記の設定で `orch-pipeline` エンジンを実行。
2. 計画は軽量に — `standard`+サイズの場合のみフル `planner` パスが必要。
3. **ゲート1**（計画/変更テスト承認）と**ゲート2**（コミット前）で停止。
4. 変更がセキュリティトリガーに触れる場合は `security-reviewer` を追加。

## 例

```
orch-change-feature: nws-pollerのアラートを3警告ではなく2警告で発動するように変更
→ 閾値テストを新しいスペックに更新 → 実装をグリーンに変更
→ コードレビュー → コミット  [ゲート2: 確認]
```
