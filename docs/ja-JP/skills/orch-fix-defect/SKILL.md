# orch-fix-defect

アクター・アクション・ターゲット: **orch · fix · defect**。[`orch-pipeline`](../orch-pipeline/SKILL.md) の共有エンジン上の薄いラッパー。

## いつ使用するか

- 何かが**壊れている**: 誤った出力、エラー、クラッシュ、リグレッション。
- 兄弟との区別：
  - 動作は正しいが異なるものにしたい → `orch-change-feature`。
  - その機能がまだ存在しない → `orch-add-feature`。

## 操作設定

- **デフォルトサイズ下限:** small（多くの場合trivial）。
- **フェーズマスク:** 0 → （根本原因が自明でない場合やstandard+の場合のみ軽量2）→ 4 → 5 → 6。Research（1）は通常スキップ。
- **最初のアクション（フェーズ4）:** バグを**新しい失敗**テスト（リグレッションテスト）として再現し、グリーンになるまで修正。バグの存在を最初に証明するのが、修正と微調整を分けるポイント。

## 仕組み

1. 上記の設定で `orch-pipeline` エンジンを実行。
2. 根本原因が不明な場合、レッドテストの前に `code-explorer` でスコープを確認。ビルドエラーは `build-error-resolver` / `/build-fix` にエスカレーション。
3. **ゲート1**（計画が生成された場合のみ）と**ゲート2**（コミット前）で停止。
4. 欠陥がセキュリティセンシティブなパスにある場合は `security-reviewer` を追加。

## 例

```
orch-fix-defect: pollerが空のNWSレスポンスでクラッシュする
→ クラッシュを再現する失敗テストを作成 → グリーンに修正
→ コードレビュー → コミット  [ゲート2: 確認]   (コミット: fix:)
```
