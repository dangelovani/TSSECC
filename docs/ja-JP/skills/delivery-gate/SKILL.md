# デリバリーゲート (Delivery Gate — Claude Code向け機械的品質ゲート)

Claudeがセッションを終了する前に3つの要素を検査する **Stopフック** です。AIによる推論ではなく、ファイルの更新日時（mtime）、ディスク使用量、会話ログ末尾に対する正規表現パターンといった**決定論的な機械的チェック**のみを使用します。

これは思考プロセスを検証するゲート（`self-audit` など）とは明確に異なります：
- **delivery-gate**: 「今日、学習ライブラリが更新されたか？ ディスク容量は安全か？」といった機械的に検証可能な事実をチェック。
- **self-audit**: 「ファイルの内容は正確か、完全か、誠実か」という4つの推論次元で出力品質をチェック。

これらは多層防御（Defense in Depth）を形成し、自己申告を鵜呑みにせず自動化された客観的エビデンスで完了を担保します。

## 検査項目

| 検査項目 | 検査機構 | 検出時の挙動 |
|---|---|---|
| **正当化（言い訳）パターン** | 会話ログ末尾に対する正規表現 | **警告のみ**（単独でブロックすることはありません） |
| **陳腐化した学習ライブラリ** | 設定された5つのパスの更新日時 (mtime) | 一部が古い場合は警告。3つ以上が古い、または複雑タスク（編集3回以上）で growth-log が古い場合は**ブロック** |
| **空きディスク容量 &lt; 50GB** | `shutil.disk_usage` | 警告 |
| **空きディスク容量 &lt; 15GB** | `shutil.disk_usage` | **ブロック** (exit 2) |

正当化検出は「とりあえずテストは後回し」「以前からあったバグ」といった、思考が途中で打ち切られた表面シグナルを警告します。正規表現による誤検知の可能性があるため、これ単独でブロックすることはありません。ブロックされる条件は「ディスク逼迫」「3つ以上の学習ライブラリが未更新」、または「複雑なタスクにおける growth-log の未更新」です。

## なぜ必要なのか

Claude Code組み込みのチェックはコード品質（ビルド → 型 → リント → テスト）をカバーします。しかし、「コードは動いたが、セッションの衛生管理が怠られた（知見が記録されていない、手抜きを正当化している、ディスクが静かに枯渇している）」という別の失敗モードが存在します。

「納品して即忘れる」セッションを繰り返しても、開発者やチームの成長資産にはなりません。本フックは「複雑なタスクを完了したら、必ず学習ライブラリに知見を残す」という習慣を機械的に強制します。

## インストール

```bash
cp quality-gate.py ~/.claude/scripts/
```

`~/.claude/settings.json` に追加：
```json
{
  "hooks": {
    "Stop": [{
      "hooks": [{
        "type": "command",
        "command": "python3 ~/.claude/scripts/quality-gate.py",
        "timeout": 5000
      }]
    }]
  }
}
```

## 学習ライブラリ (Learning Libraries)

プロジェクトのメモリディレクトリに以下のファイルを用意します。フックは今日少なくとも1つが更新されたかをチェックします：

```
memory/
├── growth-log/          # 日々の学習ログ（ディレクトリ）
├── decisions/log.md     # 意思決定ログ
├── output-index.md      # セッション成果物のインデックス
├── ratings-tracker.md   # スキル評価の推移
└── tooling_capabilities.md  # 既知ツールの台帳
```

ご自身のファイル構造に合わせて `quality-gate.py` 内の `LIBS` 辞書をカスタマイズできます。

## 設定項目

`quality-gate.py` の編集可能な変数：

| 変数名 | デフォルト値 | 用途 |
|---|---|---|
| `RATIONALIZE` | 4パターン | 正当化（言い訳）検出用の正規表現 |
| `LIBS` | 5ライブラリ | 今日の更新を確認するファイル/ディレクトリ群 |
| `COMPLEX_THRESHOLD` | 3 | 複雑なタスクと判定するEdit/Write呼び出し回数 |
| `DISK_WARN_GB` | 50 | 警告を出すディスク空き容量 (GB) |
| `DISK_CRIT_GB` | 15 | 実行を阻止するディスク空き容量 (GB) |

## 判定例

**単純なセッション — 許可:**
```
編集回数 = 1 (< 3、複雑でない) → exit 0 (正常終了)
```

**複雑なタスクで知見記録済み — 許可:**
```
編集回数 = 5 (複雑) → LIBSを検証 → growth-log が今日更新されている → exit 0
```

**複雑なタスクだが知見未記録 — ブロック:**
```
編集回数 = 4 (複雑) → LIBSを検証 → 5つすべてが未更新 → exit 2 (ブロック)
stderr: "Blocked: complex task completed but no learning captured today."
```

**ディスク容量不足 — ブロック:**
```
空き容量 = 12GB (< 15GB 危険域) → exit 2 (ブロック)
stderr: "Blocked: disk space at 12GB (threshold: 15GB)."
```

## 制限事項

本フックは学習ライブラリに記録する「習慣」を強制するものであり、記録された内容の「質」までは評価しません（内容の品質監査には `self-audit` を組み合わせてください）。

## 互換性

- Python 3.8+ (`from __future__ import annotations` を使用)
- クロスプラットフォーム対応（Windows, macOS, Linux）
- 標準ライブラリのみで動作（外部依存なし）
