# ECC レシピ集 (ECC Recipes)

「自身のワークフローを実行するにはどのECCスラッシュコマンド群を、どのような順序で実行し、どこで停止すべきか」を案内する統合エントリーポイントです。また、すべてのコマンドグループのレシピファミリーを網羅的に閲覧できます。

本スキルは以下の2つの既存スキルの隙間を埋める存在です：
- `ecc-guide` — コマンド一覧やドキュメントの参照先を示すが、フラットなカタログ形式にとどまる。
- `prompt-optimizer` — タスクをコンポーネントに適合させるが、実行順序や停止条件を伴う複数コマンド群ではなく単一のプロンプトを出力する。

本スキルが提供するもの：**ファミリー分類 ＋ 実行順序 ＋ 停止条件**。

## 発動タイミング

- 「<ワークフロー> を行うにはどのコマンドグループを実行すべきか？」
- 「MVPの構築 / 不具合修正 / リファクタリングを行うためのコマンド実行順序は？」
- 「ECCのすべてのコマンドグループレシピを見せて」（カタログモード）
- 「ECCにはどのようなワークフローパイプラインがあるか？」
- ユーザーが引数の有無にかかわらず `/ecc-recipes` を実行した場合。

### 使用してはならないケース

- ユーザーが今すぐタスクの実行を求めている場合 — コマンドを解説するのではなく、実際のコマンドへ誘導してください。
- 1つのコマンドの詳細な仕様ドキュメントが必要な場合 — `ecc-guide` を使用してください。
- プロンプトの下書きをリライトしたい場合 — `prompt-optimizer` を使用してください。

## コア原則

**メモリの記憶ではなく、現在のファイルから回答すること。** コマンドセットは進化し続けます。件数やメンバー一覧を決してハードコードしてはなりません。実行ごとに現在の `commands/` ディレクトリを読み込み、ファミリーへと分類します。

### 実行時の実ファイル読み込み

最初に存在するコマンドディレクトリを特定し、コマンド名を一覧化します：

```bash
for D in \
  "$HOME"/.claude/plugins/marketplaces/ecc/commands \
  "$HOME"/.claude/plugins/cache/ecc/ecc/*/commands \
  ./commands \
  ./.claude/commands \
  "$HOME"/.claude/commands; do
  [ -d "$D" ] && CMD_DIR="$D" && break
done
[ -z "${CMD_DIR:-}" ] && { echo "ECC commands ディレクトリが見つかりません。"; return 1; }
find "$CMD_DIR" -maxdepth 1 -name '*.md' -exec basename {} .md \; | sort
```

## ファミリー分類（プレフィックス別）

コマンド名を先頭のプレフィックスでグループ化し、単独コマンド（シングルトン）を手動でマッピングします。ファミリーは動的に導出されます。以下の表は固定リストではなく*分類ルール*です。

| ファミリー接頭辞 | レシピの意味 | 一般的な実行順序 |
|---|---|---|
| `orch-*` | タスク種別ごとのゲート付き「調査・計画・TDD・レビュー・コミット」 | タスク種別に応じて1つの orch-* を選択（内部で各フェーズを実行） |
| `multi-*` | マルチモデル・複数エージェント連携 | `multi-plan` → `multi-execute` → レビュー（または一気通貫の `multi-workflow`） |
| `prp-*` | PRDから計画、実装、PR作成までのパイプライン | `prp-prd` → `prp-plan` → `prp-implement` → `prp-commit` → `prp-pr` |
| `epic-*` | 大規模な複数ユニットの並列エピック | `epic-decompose` → `epic-claim` → `epic-validate` → `epic-review` → `epic-unblock` → `epic-sync` → `epic-publish` |
| `loop-*` | 管理された自律ループおよび監視 | `loop-start <パターン>` で開始し、`loop-status` で監視 |
| `gan-*` | 生成と敵対的評価のループ | `gan-build`（コード）または `gan-design`（UI）による自己完結ループ |
| `*-build` / `*-review` / `*-test` | 言語ごとのCIトライアド | `<言語>-test`（TDD） → `<言語>-build`（ビルド修復） → `<言語>-review` |
| `hookify-*` | 振る舞いフックの管理 | `hookify` → `hookify-list` → `hookify-configure` |
| `learn` / `instinct-*` / `evolve` / `promote` / `prune` | 継続的学習システム | `learn` → `instinct-status` → `evolve` → `promote` |
| 単独コマンド (singletons) | `santa-loop`, `plan`, `plan-prd`, `pr`, `code-review`, `checkpoint` 等 | 単独実行、またはグループ間を繋ぐ接着剤 |

## 動作の流れ

```
1. CMD_DIR からコマンド名一覧を動的に取得。
2. プレフィックスと単独マップによりファミリーへと分類。
3. ワークフローの説明が与えられた場合 -> 【マッチモード】
   説明がない場合 -> 【カタログモード】
4. 助言専用: 計画を出力する。一致したコマンドを勝手に実行してはならない。
```

### カタログモード（説明なし）

ファミリー一覧テーブル（各ファミリー名、所属件数、メンバー一覧、1行の解説、一般的な実行順序）を出力します。総コマンド数と、レシピをマッチさせるためのワークフロー入力案内で締めくくります。

### マッチモード（説明あり）

1. ユーザーのワークフローを1文で再定義する。
2. 最適な1〜2個のファミリーを選択し、その理由を1行で述べる。
3. **実行順序ブロック** — 一致したファミリーの正確なコマンド実行手順。
4. **停止条件** — 終了基準を必ず明示（最大試行回数、完了シグナル、レビュー通過、または単発実行）。自律ループの場合はトークン消費に対する警告と上限設定を推奨。
5. **ドキュメント参照先** — `commands/<name>.md` のパスおよび `/ecc-guide <name>`。

## 出力テンプレート（マッチモード）

```
対象ワークフロー: <1文での再定義>

最適ファミリー: <family> — <選定理由>
(代替候補: <family> — <選定理由>)

推奨実行順序:
  /<cmd1>   # 処理内容
  /<cmd2>   # 処理内容
  /<cmd3>   # 処理内容
  停止条件 (STOP when): <完了条件>
  警告 (自律ループのみ): 制限のないループはクレジット/利用枠を急激に消費します。
  完了シグナルと並行して、必ず最大反復回数やコスト上限のバックストップを設けてください。

詳細ドキュメント:
  commands/<cmd1>.md   (または: /ecc-guide <cmd1>)
```

## 非ゴール（行わないこと）

- コマンドの自動実行（助言のみを提供します）。
- 個別コマンドの詳細仕様の解説（それは `ecc-guide` の役割です）。
- プロンプトのリライト（それは `prompt-optimizer` の役割です）。
- コマンド件数やメンバー一覧のハードコード（常に実ファイルを動的スキャンします）。
