# Terminal Opener

実行可能ファイルおよびすべての引数を個別のプロセスエントリとして保持するために `scripts/open-terminal.js` を使用します。シェルコマンド文字列の補間は絶対に行わず、すべてのプロセス生成で `shell: false` を維持します。デフォルトでは起動を行わない計画（Plan）の生成にとどめます。実際のウィンドウ起動を行う `--launch` は、ユーザーが明示的に要求し、argvの内容が確認された後にのみ使用してください。起動されたプロセスは呼び出し元プロセスの環境変数（機密情報を含む変数を含む）をそのまま継承します。ランチャーは環境変数のフィルタリングを行いません。対象コマンドに公開しても安全な環境変数を持つシェルから実行してください。

## コマンドの起動

ランチャーのオプションを `--` の前に指定し、その後に1つの実行可能ファイルと引数配列を渡します：

```bash
node skills/terminal-opener/scripts/open-terminal.js \
  --launch \
  --cwd /absolute/host/path \
  -- ssh -t example.test command-with-arguments
```

まずは通常モードで実行します。WezTermのmuxによる新規ウィンドウの作成を試行させ、muxが利用できない場合はランチャーをデタッチされた `wezterm start` プロセスへとフォールバックさせます。フォールバックが発生した場合は、JSON出力の `muxFailure`（またはエラーメッセージ行）を確認し、muxパスが失敗した原因を診断してください。

## ターミナル設定起因の不具合からの復旧

ユーザーのターミナル設定やmuxの状態が要求されたコマンドと干渉する可能性がある場合は、`--recover` または `--standalone` を追加します。以下のオプションでデタッチされたWezTermプロセスを起動します：

```text
--skip-config start --always-new-process
```

復旧モードでは、ユーザーのターミナル設定が意図的にすべてスキップされます。

## 起動前の検証・検査

ウィンドウを開かずに、実行ファイル、argv、作業ディレクトリ、ターミナルアダプター、プライマリ起動、フォールバック構成を正確に検査するには、`--launch` を省略（または `--dry-run` を付与）して `--json` を指定します。呼び出し元との連携境界としてこのJSONプランを利用してください。

コマンドを指定せずに `--detect --json` を実行すると、ターミナルの利用可能性をプローブできます。アダプターが見つからないか未サポートの場合は、返された `action` の指示に従ってください。現在のアダプターとしてはWezTermを使用します。その他のターミナルが要求された場合は、直接実行するのではなく、未サポート計画として扱ってください。
