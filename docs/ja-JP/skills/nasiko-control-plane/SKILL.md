# Nasiko CLI ライフサイクルブリッジ

ユーザーからECCに対して、適格性が検証されたNasiko CLIのインストール、検査、または削除の明示的な要求があった場合に本スキルを使用します。本スキルはNasikoコントロールプレーン自体の運用は行いません。

## 安全性規約（Safety Contract）

- まず `ecc nasiko status --json` から開始します。ステータス確認は読み取り専用です。
- インストールには常にユーザーの明示的な同意と `--yes` フラグが必要です。
- ECCが適格性を検証・固定したバージョン（現在は `v0.1.0`）のみをインストールします。
- 事前に `ecc nasiko install --version v0.1.0 --dry-run --json` でプレビューを行います。
- ユーザーがバージョン、レジストリ元の出所、ダイジェストハッシュ、および配置先を確認した後にのみ、`ecc nasiko install --version v0.1.0 --yes --json` でインストールを実行します。
- 削除は、ECC管理下にある適格バイナリに対してのみ `ecc nasiko uninstall --version v0.1.0 --yes --json` を使用して行います。削除前にも必ず `--dry-run` でプレビューしてください。
- 検証済みソースは `https://github.com/Nasiko-Labs/nasiko`（Apache-2.0ライセンス）であり、成果物および展開後のバイナリのSHA-256ハッシュ値は固定されています。
- 検証済みコマンドの代わりに、外部からダウンロードしたシェルスクリプトやPowerShellブートストラップスクリプトを代用してはなりません。
- コマンド引数、ログ、スキルの出力、インストールメタデータ、ECCの状態内にシークレットや認証情報を含めてはなりません。
- NasikoのテレメトリやNasiko/Itôへのデータ共有はオプトインであり、個別に開示される必要があります。ツールのインストールはテレメトリへの同意を意味しません。

## ライフサイクルの境界

初期のECCブリッジは、適格バージョンのインストール、読み取り専用ステータス確認、および所有権確認付きアンインストールをサポートしています。接続、認証、起動、デプロイ、シャットダウンなどの操作については、各操作の検証済みECC規約が策定されるまで、正規のNasiko CLIを直接使用してください。未検証のCLIサブコマンドを推測で実行しないでください。

CLIをインストールしたことは、コントロールプレーンサーバーが稼働中であること、エージェントが統括されていること、ルーティングやACLが機能していること、オブザーバビリティが万全であること、テレメトリが有効化されたこと、あるいはItôコンピュートが接続されたことを意味しません。それぞれの状態を個別に報告してください。

## 障害時の挙動

- プラットフォーム、アーキテクチャ、バージョン、マニフェスト、ダイジェスト、アーカイブ、バイナリ、配置先のいずれかで検証に失敗した場合は、成果物を実行せずに即座に停止します。
- `latest` へのフォールバックは絶対に行わないでください。
- 任意の `PATH` を勝手に探索しないでください。開発検証にはECCの検証済み配置先または明示的な絶対パス `ECC_NASIKO_CLI_EXECUTABLE` を使用してください。
- 不完全または曖昧なインストール状態を成功とみなしてはなりません。
