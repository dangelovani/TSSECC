# Taste Application（テイストの適用と映像編集）

パイプラインの後半部分です。**taste-distillation** がリファレンスを測定してスタイルパックを作成し、本スキルがそのパックに基づいて生成とカット割り（編集）を行います。

## 実行および納品契約

元の実装は `scripts/` に同梱されており、個別の外部チェックアウトは不要です。ローカル処理には `scripts/requirements.txt` をインストールします。外部プロバイダー（fal等）の実行には `scripts/requirements-live.txt` をインストールしてください。ライブ環境でのアップロードやジョブ送信には、資格情報に加えて明示的な `TASTE_FORGE_ALLOW_LIVE=1` が必要です。`--dry-run` は認証情報なしで動作し、ラベル付きプレースホルダーを出力します。曖昧なプロバイダータイムアウトが発生した場合、自動で新しい有料ジョブを再試行してはなりません。

プロバイダーを呼び出さず、既存の完成テイクのみを使用する場合:

```bash
python scripts/pipeline.py --genre example --root stylepacks \
  --takes media/take-a.mp4 media/take-b.mp4 --duration 12 --fps 30 \
  --out out/review-v1.mp4
```

`--duration` は**ベストエフォートのカット周期目標**であり、厳密な再生時間ではありません。完全なショットを優先するため、編集結果は目標よりわずかに短く、あるいは長くなる場合があります（アセンブラーが尺合わせのためにクリップを不自然に複製したり余白を追加することはありません）。出力マニフェストには実際の再生時間と、目標との差分が記録されます。

編集可能な FCPXML および EDL が参照するため、パイプラインは各実行のグレーディング済み個別ショットファイルを保持します。レンダー完了は、編集ソフト側のプロジェクト保存やクリエイティブ承認と同一ではありません。編集前後のソースアセットおよびプロジェクトのチェックポイントを確実に保存してください。

## 有効化のタイミング

- 「このスタイルで動画を作ってほしい」/「スタイルパックを適用して」/「この映像を補完・拡張して」
- 生成されたクリップ群を、本物の編集リズムを持った作品にまとめ上げるとき
- ルックから3Dプロップを生成し、それを動画内に合成して戻すとき
- 完成した作品がリファレンスと実際に一致しているかを数値的に検証するとき

## 役割分担（Division of Labour）

**モデルはコンテンツ、モーション、フレーミング、ライティング構造を提供する。スタイルパックは色彩とリズムを提供する。** これは単なるスタイルの好みではなく測定に基づく客観的事実です:

- 生成プロンプトには**色に関する単語を一切含めない**こと。*「Colour: none. Render neutral. Grading is applied afterwards.（色: なし。ニュートラルにレンダリングすること。グレーディングは後から適用される）」* と明記します。
- **2つのフラグを分離する**: `--brief`（何が起きるか: 被写体、アクション、場所）と `--style-steer`（どのように見えるか）。これらを混ぜると、スタイルの単語がシーンに漏れ出したり（「ティール」と言っただけで被写体が青緑色になる）、被写体の単語がグレーディングに影響してしまいます。
- モデルは抽象的な指示よりも**具体的で検証可能なルール**に敏感に反応します。「背景は純黒で照明なし、被写体は白飛び寸前のハイライト」は機能しますが、「極端なコントラスト」は機能しません。

## ショットではなく「テイク（TAKES）」を生成する

「カット周期を合わせる」という指示を素朴に解釈して1ショットごとに1回の生成を行うのは、経済的にも品質的にも破綻しています。平均0.78秒/ショットのリファレンスに対して最小4秒の生成エンドポイントを使用すると、10秒の動画を作るのに**12回のAPI呼び出し、48秒の生成に対して使用されるのは10秒（効率21%）**となり、無関係な12本のクリップをつなぎ合わせただけの不自然な映像になってしまいます。

人間のエディターは長めのテイクを回し、その中からカットを切り出します。約5秒のテイクにショットをまとめることで、**3回の呼び出し、13秒の生成で効率77%**を達成でき、同一の生成から切り出された連続ショットは自然な一貫性を保ちます。

モデルには、内部にハードカットを含まない連続した動きを指示します:

> "Filmed as ONE continuous take with no hard cuts inside it. It will be cut into 6 pieces of roughly 0.8s in the edit, so the framing, subject and light must keep changing throughout — any 0.8s window has to stand alone as its own shot."（内部にハードカットを含まない1つの連続した長回しとして撮影すること。編集時に約0.8秒の6つの断片にカットされるため、フレーミング、被写体、光が常に変化し続け、どの0.8秒を切り出しても独立したショットとして成立するようにすること。）

## カッティング（編集）ルール

- **ストリームコピーは禁止、必ず再エンコードすること。** ストリームコピー（`-c copy`）はキーフレーム単位でしかカットできないため、平均0.78秒のショット長において境界が最寄りのGOPに丸められ、厳密なリズムが完全に破壊されてしまいます。
- **既存映像を補完する際は、その素材自身のショット境界を使用する。** ベース動画を等間隔に切り刻んでそのまま並べても、元の映像が再生されるだけでカットが不可視になります。実際のシーン変化境界を検出し、N個おきにサンプリングして連続するクリップの不連続性を保証してください。
- **リファレンスの平均値ではなく、分布（distribution）からショット長をサンプリングする。** これにより、機械的な均一尺ではなく、生きたリズムの揺らぎを継承できます。

## グレーディングルール

- クリップが手元にある場合は、**ベイク済みLUTよりも直接測定（Direct measurement）が優れている**。クリップを測定し、L\* CDFをマッチさせ、ゾーン別クロマを適用します。
- **クリップのヒストグラムがリファレンスと大きく異なる場合は、CDFマッチングではなくアンカー方式を採用する。** 68%が黒の生成クリップを情報量の多いリファレンスのヒストグラムに無理やり合わせると、背景の黒が浮いてグレーになってしまいます。デフォルトはアンカー方式のトーン補正とします。
- **バッチサイズに注意。** 48フレームを一括処理するとOOM（メモリ不足）でクラッシュします。6フレーム単位が安全です。

## 画面録画素材のUI被り（Capture App's UI）の除去

納品された映像に見られる最悪の欠陥の1つは、元映像が画面録画であったために、他人の「いいねボタン」「再生数カウンター」「コメントアイコン」が画面端に残ってしまうことです。

時間的分散（Temporal variance）だけではこれを除去できません。いいねのハートが鼓動したりカウンターが動くため、動的コンテンツと誤認されるからです。**時間的中央値（Temporal median）**を指標とします。映像は動くため中央値を取るとエッジがぼやけますが、UIは固定座標にあるためエッジが鮮明に残ります。中央値フレームに対する Sobel フィルタによってUI部分のみを明確に検出し、確実にクロップ除去してください。

## オーバーレイプレートの合成

グロー（光彩）プレートは画面の数％しか占めない要素です。フレーム全体にそのまま合成すると、画面中央に小さな明るい点が浮いているだけの不自然なシールのように見えてしまいます。

- **まず各プレートをアルファバウンディングボックスまでタイトにクロップする。** これにより余白を排除し、呼び出し側でスケールを正確に制御できるようにします。
- **被覆率に応じて全体ウォッシュ（拡散光）か個別要素（ピンポイント）かを使い分ける。**
- シード値付き乱数によって**ショットごとに配置、スケール、回転を変化させる**。毎回同じ位置に出すと透かし（ウォーターマーク）のように見えてしまいます。

## 後工程への引き渡し（DaVinci Resolve / Blender）

**mp4動画とともに、必ず編集可能なタイムライン（FCPXML 1.9 / CMX3600 EDL）を納品すること。** レンダリング済みの単一動画はプレビュー用に過ぎず、すべてのカットが焼き付けられているためカラリストやエディターが再調整できません。

注意点:
- **インポート前にプロジェクトのフレームレートを設定すること。** Resolve は最初のタイムライン作成時にプロジェクトfpsを固定し、異なるfpsのクリップを暗黙的にコンフォーム（速度変換）してしまいます。サブセクション秒のカットではこのズレが致命的になります。
- **納品される個別ショットはすでにグレーディング済みである。** `look.cube` を再度適用すると二重グレーディングになってしまいます。

Blender との連携において、`scripts/blender_prop.py` はスタイルパックからライティングを導出します（透明フィルム付きの黒ワールド、キーライト＋リムライト、ピーク彩度ゾーンから変換されたリムライトカラー）。**View Transform は AgX や Filmic ではなく Standard を使用し、Blender 内での二重グレーディングは行わないでください。**
