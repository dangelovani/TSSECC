# Itô 分散学習 (Itô Training)

`ito-training` は、Itôコンピュート上での機械学習モデル学習を扱う正規のECCスキルです。ECC自体は独自のトレーナー、スケジューラ、データパイプラインを実行することはなく、予約、確保、支払いも行いません。本スキルは、`ito-compute` で行われた**完了済みの予約**を前提として連動します。

## 現在の本番環境境界（Current Production Boundary）

現在、マネージド学習機能は提供されていません。ECCブリッジは `login`、`logout`、`auth`、`find`、`status`、および明示的にゲートされた `evals` のみを公開しています。`train` サブコマンドは存在せず、正規CLIの `run` サブコマンドやデスク側の `training-run` バックエンドもドラフト段階です。局所的に強制される保証として、ECCは認証情報を持つ正規クライアントを解決・生成する前に `train` を拒否します。

したがって、認証やコマンドの実行を行う前に停止してください。機能が存在しない旨を報告し、呼び出し元のエージェントに制御を戻してください。ローカルのトレーナー、SSHヘルパー、ブラウザワークフロー、購入エンドポイントなどで勝手に代用してはなりません。

## 必要な利用資格（Required Entitlement）

学習機能が実装された際の最初のゲートは、「サーバー側で検証済みの完了した予約」です。ハーネスのメモリ、RFQ、見積もり、ノードIP、SSHアクセスなどは利用資格のエビデンスにはなりません。バックエンドが、認証されたアカウント、予約、GPUトポロジー、リージョン、ファブリック、期間に紐づいた最新の学習適格性を返却する必要があります。期限切れ、取り消し済み、不一致、不完全、または解放済みの予約は、確認を行う前にフェイルクローズ（安全側に倒して拒否）されます。

## 将来のCLIおよびAPI規約

予定されているコマンド名は `train` です。将来の引き渡しは以下と同等でなければなりません：

```sh
ecc ito train \
  --booking <サーバー検証済み予約ID> \
  --manifest <レビュー済みの絶対パスJSONファイル> \
  --confirmation-ref <非認可の不透明な確認参照ID> \
  --idempotency-key <安定した再試行キー> \
  --json
```

レビュー済みマニフェストには、モデルサイズとリビジョン、除染（Decontamination）の出所が明記されたデータ参照、学習ターゲット、事後学習レシピ、USD単位の予算上限、チェックポイントポリシー、最大追加コストを明記する必要があります。生のAPIキー、SSHキー、ノードパスワード、ベアラートークン、データセットの認証情報を引数、マニフェスト、ログ、MCP結果、チャットに含めてはなりません。

クライアントはマニフェストのパスを正規化し、シンボリックリンクを拒否し、リンクを追従せずに通常ファイルを開き、適切な所有権と制限されたアクセス権を要求し、サイズ上限を強制し、開かれたファイルディスクリプタからバイト列をハッシュ化しなければなりません。そのダイジェストハッシュは、ワークロード変更前に確認情報にバインドされたダイジェストと完全に一致しなければなりません。パスのすり替え、ダイジェスト不一致、サイズ超過、変更可能な危険なファイルはすべてフェイルクローズされます。

ECCではなく正規APIがワークロードの作成を管轄し、`ok`、`live_api_contacted`、`notice`、および `data` または `error` を含む構造化JSONを返却する必要があります。学習データには、安定した予約ID、実行ID、マニフェストID、冪等性キーID、および状態Enumを含める必要があります。エラーには、シークレットを含まない安定したエラーコードと安全なメッセージを含める必要があります。

## 確認および実行ゲート

ワークロードの作成前に、以下のすべてを必須とします：

1. 正規バックエンドからの最新の利用資格および学習適格性の確認。
2. レビュー可能で不変のマニフェストと決定論的なダイジェストハッシュ。
3. 短い有効期限とリプレイ防止機能を備えた、アカウント、アクション、マニフェスト、コストに紐づく個別の1回限り確認。CLI引数は不透明で単独では認可力を持たない確認参照IDのみを渡し、サーバーがアウトオブバンドでベアラー機能を解決・消費します。
4. 実行とアトミックに予約される、呼び出し元提供の冪等性キー。
5. マニフェストの予算上限を含む、サーバー側でのファブリック、容量、データポリシー、チェックポイントストレージ、コストの検証。

認証は「身元」の証明であり、「ワークロード作成の権限」ではありません。ログイン、APIキー、見積もり、完了した予約をもって学習確認の代わりとすることはできません。検査や計画の生成によってワークロードを作成してはなりません。キャンセルやクリーンアップは、独自のスコープ付き確認と冪等性境界を持つ個別の変更操作です。

## ライフサイクルと復旧

正規クライアントがテナントスコープのステータス確認、ログ、メトリクス、チェックポイント一覧、キャンセル、クリーンアップ操作を公開するまで、本番サーフェスは未完成です。すべての操作に接続タイムアウトと全体タイムアウト、取り消しを認識するエラーハンドリング、構造化出力が必要です。曖昧なトランスポート障害が発生した場合は、再試行する前に冪等性キーでステータスを照会してください（単に応答が失われたという理由だけで2回目の学習実行を開始してはなりません）。認証情報が取り消された場合はポーリングを停止し、自動的にログインを再試行することなく呼び出し元エージェントに制御を戻します。

ステージゲートの結果は誠実に報告してください。失敗した評価ゲートを勝手にオーバーライドしてはなりません。クリーンアップは観測可能でなければならず、基盤となる予約を解放または変更してはなりません（その個別の経済的アクションが明示的に認可されている場合を除く）。

## 提案されているバックエンドステージ

以下のステージはECC内のコードではなく、将来のバックエンド（Layer 0.3）の動作を示したものです：

1. **データ準備:** マニフェスト、重複排除、評価スイートに対するデータ除染。カスタムデータの安価な事前チェックとしての150M規模の予備検証ジョブ。
2. **並列化と精度:** モデルサイズ、ノード数、ファブリックから自動選定（非効率な組み合わせは拒否）。
3. **チェックポイントとフォールトトレランス:** 非同期DCP、torchft（10分未満での検知、15分未満での再開）。損失急増（Loss-spike）時の再起動は人間がゲートする提案アクション。
4. **カリキュラムと評価ゲート:** 段階的な事前学習 / 中間学習 / 長文コンテキスト / 事後学習。それぞれに固定の評価セットを用意し、ゲート失敗時は実行を停止。
5. **事後学習:** SFT → DPO → RLVR (DAPO安定化修正を施したGRPO)、有限の遅延許容を伴うトレーナー/ロールアウト分離。

バックエンドはデスクのテレメトリ（実効スループットgoodput、中断率、チェックポイント帯域幅）を出力し、デスクが学習ブロックを適正に値付けできるようにします。

上記のすべてのゲートおよびライフサイクル操作が正規ランタイムに実装されるまで、本スキルはフェイルクローズな利用可能性チェックおよびドキュメント引き渡しにとどまります。
