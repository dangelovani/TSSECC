# orch-add-feature

アクター・アクション・ターゲット: **orch · add · feature**。[`orch-pipeline`](../orch-pipeline/SKILL.md) の共有エンジン上の薄いラッパー。

## いつ使用するか

- ユーザーが**まだ存在しない**機能を求めている場合（「追加」「構築」「実装」「〜をサポート」）。
- 完全に新しい動作 — 修正（`orch-fix-defect`）でも既存動作の変更（`orch-change-feature`）でもない。

## 操作設定

- **デフォルトサイズ下限:** standard — 明らかに小さくない限り、Research + Planを実行。
- **フェーズマスク:** 0 → 1 → 2 → 4 → 5 → 6（3 Scaffoldはスキップ。MVPのみ）。
- **最初のアクション（フェーズ4）:** 新しい動作の*新しい*失敗テストを書き、グリーンになるよう実装。

## 仕組み

1. 上記の設定で `orch-pipeline` エンジンを実行。
2. まずサイズを分類。小さい/些細な機能は 4 → 5 → 6 に集約。
3. **ゲート1**（計画承認）と**ゲート2**（コミット前）で停止。
4. 機能がセキュリティトリガーに触れる場合は `security-reviewer` を追加。

> 関連: `/feature-dev` はこのフローのスタンドアロン版。`orch-add-feature` は `orch-pipeline` エンジン（サイズ分類器と2つのゲート）をファミリーの他のメンバーと共有する点が異なり、些細な機能を 4 → 5 → 6 に適正化する。

## 例

```
orch-add-feature: nws-pollerにOAuth2ログインを追加
→ 既存認証ライブラリを調査 → タスクリストを計画  [ゲート1: 承認]
→ 各タスクをTDD → コードレビュー（+ security-reviewer: 認証パス）
→ コミット  [ゲート2: 確認]
```
