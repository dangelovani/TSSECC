# TasteForge Video（TasteForge 動画制作パイプライン）

完全に独立したクリエイティブパイプライン全体を実行する場合は、まず `taste-distillation`、次に `taste-application` を使用します。これらのECCスキルにはPythonスクリプトが直接同梱されています: リファレンスの測定、既存カットの生成またはパススルー、グレーディング、編集（カット割り）、合成、検証、およびBlenderやDaVinci Resolveへの引き渡し。そのフローには個別の外部動画リポジトリは不要です。本スキルは、ECCにパッケージ化されたオフラインエンジンと、その厳格なエビデンス契約（制約仕様）を規定します。

TasteForge は、「このリファレンスのような雰囲気にしたい」という曖昧な要望を、再現可能で検査可能なワークフローに変換します: テイストをインタビューし、構造化されたスタイルパックへと蒸留し、パックを検証し、測定されたリズム（カット周期）とルックをローカルメディアに適用して、編集可能なタイムラインをエクスポートします。公式の実装は、ECC内部の `skills/taste-application/scripts/tasteforge/` に同梱されている `tasteforge` パッケージです。`Ito-Markets/ito-video` は、このパッケージ化されたECCエンジンを利用するプロジェクト例です。

## 使用場面

- 映像制作に着手する前に**動画のテイストをインタビュー**したいとき（「ルックについて質問してほしい」「美的方向性についてインタビューしてほしい」など）。
- 曖昧なフィーリングではなく、**美学を構造化された制約（再利用可能なスタイルパック）へと蒸留**したいとき（「これらのリファレンスをパックにしてほしい」）。
- **スタイルパックを検証**したいとき（メタデータが完全か、スキーマに適合しているか、カット周期が測定されているか、仕様が蒸留されているか）。
- **スタイルパックをローカル映像に適用**したいとき — パックの測定されたカット周期に基づいて、決定論的にローカルクリップのカット割りを計画する。
- **EDL/FCPXML をエクスポート**したいとき — DaVinci Resolve、Premiere、Final Cut Pro へフレーム単位で正確に引き渡せる編集可能データ。
- **生成メディアの出所（来歴/プロベナンス）監査**を行いたいとき — このパック、仕様、またはカットはどこから来たのか。何がローカルで測定され、何が外部プロバイダーで生成されたか、何がドライランか。
- ローカルリファレンスファイルから、個別のマニフェスト、被写体アンカー付きCVエフェクト、Resolveエフェクトレシピを含む、**ファイル駆動のマルチモーダル画像・動画・3Dアセット出力を探索または計画**したいとき。
- TasteForge、スタイルパック、flashethereal、テイスト蒸留、カット周期/リズム計画、マルチモーダル探索、蒸留/適用ワークフロー、または動画のテイストインタビューに言及されたとき。

## ローカル決定論的処理 vs プロバイダー生成

この境界線こそが、本スキルの最も重要なコアです。本スキルの操作は**ローカル、決定的（deterministic）、かつオフライン**です:

| 操作 | 決定論的か？ | ECCで実行可能か |
|---|---|---|
| テイストインタビュー → プロファイル作成 | はい（オフライン） | はい |
| パックの検査 / スキーマに対する検証 | はい | はい |
| プロファイルの蒸留（＋測定されたグラウンディング） → 仕様書 | はい（ドライランセマンティクス） | はい |
| パックのカット周期をローカルメディアに適用 → レポート ＋ タイムライン | はい | はい |
| EDL（CMX3600）/ FCPXML 1.9 のエクスポート | はい | はい |
| 出所 / 来歴レポートの作成 | はい | はい |
| スティル画像のビジョンモデルによる蒸留 | **プロバイダー生成** | **いいえ** |
| リファレンスからの動画生成、画像からの3D生成、ホスト側合成 | **プロバイダー生成** | **いいえ** |

**プロバイダー生成は ECC において必ずフェイルクローズ（安全停止）しなければなりません。** Fal などのプロバイダーに対する実際の呼び出し（ショットの生成、プロップメッシュの鋳造、ホスト型VLMによる蒸留）は、個別に認可された別の実行レーンと独自のレビューが必要です。この互換レーンにおいて、ECC が Fal を呼び出すことは決してなく、APIキーや資格情報（`FAL_KEY` を含む）を読み取ることもなく、メディアをアップロードすることも、プロバイダーのアカウント状態を変更することもありません。プロバイダー生成が必要な要求に対しては、この境界を明確に説明した上で、ローカル側（インタビュー、パック検証、計画、エクスポート）のみを実行して停止してください。

**「Falのワークフローが保存された」と主張してはなりません。** パックのメタデータ内に現れる Fal のエンドポイント、モデルID、ドライランURLへのローカル参照は**単なる参照情報**に過ぎません。外部プロバイダー側にワークフローが保存・永続化されたことや、実行が認可されたことを意味するものではありません。オフラインで生成されたものはすべてドライラン（dry-run）の性質を持ちます — 「モデルによって生成された」ではなく、「ドライラン仕様」または「決定論的計画」と表現してください。

## 正式な実装

- リポジトリ: `affaan-m/ECC`。Pythonディストリビューション `ecc-tasteforge`、パッケージディレクトリ `skills/taste-application/scripts/tasteforge/`。抽出されたECCパッケージから `python3 -m pip install ./skills/taste-application/scripts` でインストールします。
- CLI: `python3 -m tasteforge <command>` — `provenance`, `inspect`, `validate`, `interview`, `distill`, `apply`, `export`, `multimodal`。`--live` フラグは終了コード2で拒否されます。
- スキーマが厳格な契約となります: テイストプロファイル、パックマニフェスト、グレーディング、カット周期、仕様書、タイムラインイベント、適用レポート（`provider` は `"none"` に、`dry_run` は `true` に列挙型で固定されています）。

## クリエイティブスキルの連携

| ステージ | 担当スキル | レビュー可能な成果物 |
|---|---|---|
| クリエイティブディレクション | `taste` | 指名されたジャンル、リファレンスの観察結果、選択されたルック、除外リスト |
| 蒸留と計画 | `tasteforge-video` | 測定されたエビデンス、ジャンル別の個別仕様書、ドライランマニフェスト、カット周期計画 |
| 編集とエフェクト | `video-editing`（Remotion, Manim, Fusion等） | 適用された映像、実際のトラック、編集可能なエフェクトとタイムライン |
| アセット生成や音声（オプション） | `fal-ai-media` または音声ワークフロー（個別認可下） | プロバイダーのレシートと検査済み出力 |
| 納品・配信 | 編集ワークフロー、および要求に応じた `content-engine` | レビュー済みのエクスポートデータと配信コピー |

プロジェクトが必要とするステージのみを使用してください。3Dリクエストマニフェストはアセットの計画であり、メッシュそのものではありません。被写体アンカー記述子はトラッキングの要件を指定するものであり、被写体が実際に検出・トラッキングされた証拠ではありません。CVエフェクトが確実に適用されたと主張する前に、実際のトラッキング挙動やレンダリング結果を確認してください。

## ワークフロー

1. **インタビュー（`interview`）:** ルックの各軸（パレット、グレイン、ライティング、焦点距離、カメラワーク、被写体フレーミング、グレーディング、ムード形容詞、除外リスト）およびコンテンツブリーフに対する回答を収集します。ルックとコンテンツを混同せず分離して管理します。
2. **蒸留（`distill`）:** プロファイルをオフラインで仕様書スキーマにマッピングします。パックが提供されている場合は、測定されたグラウンディング（黒レベル/白レベル、コントラスト、ゾーン別彩度、パレット、カットリズム）を埋め込みます。結果は決定論的なドライラン仕様（provider: `"none"`）となります。
3. **検証（`validate` / `inspect`）:** パックをスキーマと照合して検査します（メタデータのみのパックにおいてスティル画像がない場合はエラーではなく警告として扱います）。
4. **適用（`apply`）:** ユーザーのローカルクリップに対して、パックの測定されたカット周期からシード値に基づく決定論的なショット長を計画し、適用レポートとフレーム精度のタイムラインイベントを生成します。
5. **エクスポート（`export`）:** 実際のNLE（動画編集ソフト）にインポート可能な、CMX3600 EDL および FCPXML 1.9 を出力します。
6. **監査（`provenance`）:** 復元されたソースのダイジェスト、生成履歴、フィクスチャの出所、ポインタのみのプロバイダー参照などの来歴をレポートします。

### 重複のない実映像のカット割り計画

クリップの重複を禁止するブリーフの場合は、`apply --no-repeat --fps` をサポートする正規のチェックアウトを使用し、出力フレームレートを明示的に設定します。厳格モードでは、正規化された各ソースパスをマニフェスト順に最大1回のみ使用し、ソースが不足している場合はエラーとします。カット周期計画を満たすのに十分なレビュー済み素材を準備してください。

エクスポートCLIは `{"clips": [...]}` を想定しています。適用処理で得られた `timeline_events` を `clips` の下にラップしてからエクスポートし、適用時と同じ `--fps` を渡してください。

## ファイル駆動マルチモーダル契約（File-Driven Multimodal Contract）

ローカルリファレンスから画像、動画、および3Dアセットのドライラン生成計画をジャンル分離を維持したまま策定する場合に使用します:

```bash
python3 -m tasteforge multimodal --config workflow.json --out-dir out/multimodal
```

候補ジャンルは混同せず明確に区別します:
1. Flash Ethereal
2. 3D Cyber Glitch
3. Fluid Sketch

コマンドは ffprobe/ffmpeg でローカルリファレンスを測定し、ジャンルごとに1つのスタイル仕様書、個別の画像/動画/3Dアセットマニフェスト、出所記録、および Resolve エフェクトレシピを出力します。CVエフェクトには、ロスト時のポリシーが厳格に `disable_effect_until_track_recovers` に設定された正規の被写体アンカーが必要です。顔や読みやすいタイポグラフィを保護する配置制約がすべてのエフェクトに付与されます。

返されるレシートはバンドルの境界となります。すべての成果物を相対パス、バイトサイズ、SHA-256、ジャンル、モダリティ、`provider_execution:false`、および正確なリファレンス/時間情報にバインドします。レシートには整数値としての `provider_calls:0`（真偽値は無効）、`provider_execution:false`、および `dry_run:true` が必須です。作成後は必ずバンドル検証を実行し、不整合がある場合はフェイルクローズします。

## セッション例

```bash
# ECCエンジンのインストール後。パスはプロジェクトの入力
python3 -m tasteforge validate stylepacks/flashethereal
python3 -m tasteforge interview --answers answers.json --genre flashethereal --out profile.json
python3 -m tasteforge distill --profile profile.json --pack stylepacks/flashethereal --out spec.json
python3 -m tasteforge apply --pack stylepacks/flashethereal --media media.json --duration 20 --out report.json
python3 -m tasteforge export --events events.json --out-dir out --title flashethereal-cut
python3 -m tasteforge provenance
```

ショットを実際に生成する必要がある場合は、ユーザーの明示的なプロバイダー認可のもとで、レビュー済みのブリーフとスタイル指示を `taste-application` に渡してください。オフラインCLIは常にフェイルクローズを維持します。
