# 動的ワークフローモード (Dynamic Workflow Mode)

コーディングエージェントが静的なコマンドフローに従うだけでなく、タスクローカルな専用ハーネス（実行基盤）を動的に生成・適応できる場合に本スキルを使用します。単発作業用の一時的ハーネス、反復作業から抽出される共有スキル、チーム向けの観測可能なコントロールパネルのチェックポイントを組み合わせ、動的ワークフローを規律あるエンジニアリングシステムへと昇華させます。

## 発動タイミング

- ユーザーが動的ワークフロー、カスタムハーネス、タスク別ハーネス、適応型ワークフロー、またはClaude Codeの動的ワークフローモードに言及した場合。
- タスクが独自のループ、評価器（Evaluator）、クローラー、テストフィクスチャ生成器、ウォッチャー、またはローカルダッシュボードを必要とする場合。
- 複数のエージェントが同じ反復プロセスを必要としているが、まだ共通スキルとして体系化されていない場合。
- ワークフローがマージ前に永続的なハンドオフ成果物、評価エビデンス、またはオペレーターの承認を必要とする場合。

## コア規約 (Core Contract)

タスクローカルなハーネスは、「同じ手順を手動で進めるよりも低コストかつ安全である」場合にのみ生成します。ハーネスは以下の要素を必ず備えている必要があります：

- **目標 (Objective)**: 責任を持つ成果物と、明示的にスコープ外とする対象。
- **入力 (Inputs)**: ファイル、URL、プロンプト、データソース、認証情報ポリシー、ユーザー指定の制約条件。
- **出力 (Outputs)**: コミット、レポート、スクリーンショット、ステータスファイル、コントロールパネルのスナップショット。
- **評価 (Eval)**: 単に「動いた」だけでなく、タスクに直結した少なくとも1つの成否（Pass/Fail）判定。
- **ハンドオフ (Handoff)**: 何が起きたか、何がブロックされているか、どう再開すべきかを次の担当者に伝える簡潔な成果物。

## 動的ハーネスの意思決定ツリー

1. **1回限りのタスク:** インラインで完結させる。ハーネスを無駄に作らない。
2. **入力が変わる反復タスク:** タスクローカルなハーネスを作成し、一時領域またはプロジェクトローカルな作業領域に保持する。
3. **チームメンバー間や複数リポジトリで繰り返されるタスク:** パターンを抽出して共通スキル化する。
4. **外部状態、キュー、承認が絡むタスク:** 自動化を増やす前に、まずコントロールパネルで可視化する。
5. **安全リスクのあるタスク:** 自律実行の前に、評価ゲートと人間によるマージゲートを設ける。

## タスクローカルハーネスのテンプレート

コードを書く前に以下の構造を定義します：

```markdown
# 動的ワークフローハーネス

目標 (Objective):
- 達成すること:
- 行わないこと:

入力 (Inputs):
- リポジトリまたはワークスペース:
- 外部システム:
- 認証情報ポリシー:

ループ手順 (Loop):
1. 現在の状態を調査・把握する。
2. 最小限の有用な成果物を生成または更新する。
3. 評価（Eval）チェックを実行する。
4. ステータスとハンドオフを記録する。
5. ゲート失敗、所有権不明、安全でない外部操作が検知されたら停止する。

評価 (Eval):
- 実行コマンド:
- 合格判定のシグナル:
- 失敗時の責任者:

ハンドオフ (Handoff):
- ステータス:
- エビデンス:
- 次のアクション:
```

## 共通スキルの抽出基準

タスクローカルなハーネスを共通スキルへ昇格させるのは、以下のうち少なくとも2つが当てはまる場合のみとします：

- 同じワークフローが複数のセッション、リポジトリ、チーム、ローンチで繰り返し登場する。
- ワークフローが特定の言語、ツール、安全性の順序付けを必要とする。
- 担当者がゲートをスキップしたりコンテキストを見失ったりして失敗が再発している。
- ワークフローが安定した入力/出力規約を持っている。
- コントロールパネル、ステータスボード、チームハンドオフによる恩恵が大きい。

抽出時は、まず `skills/<name>/SKILL.md` にスキルを作成します。レガシーなスラッシュコマンド互換が必要な場合のみコマンドシムを追加します。

## コントロールパネルのチェックポイント

タスクが複数セッションにまたがる場合は、状態を公開してチームで共有可能にします：

- **Plan（計画）**: 目標、所有者、受入基準、リスクのある外部システム。
- **Queue（キュー）**: 作業項目、割り当てられたエージェントロール、ブランチ/ワークツリー、依存関係。
- **Run（実行中）**: アクティブなハーネス、現在のループステップ、直近の評価結果、トークン/コスト情報。
- **Gate（ゲート）**: テスト結果、ブラウザスクリーンショット、セキュリティレビュー、マージ準備状況。
- **Handoff（引き継ぎ）**: 完了事項、失敗事項、人間の判断を仰ぐ事項。

## 評価ゲート (Eval Gates)

作業の種類に応じて、最も安価で信頼性の高いゲートを選択します：

| 作業種別 | 推奨評価ゲート |
| --- | --- |
| コード機能 | フォーカステスト、リント、カバレッジ、1本の統合テスト |
| UI / コントロールパネル | スクリーンショット、オーバーフロー/エラー検証を伴うブラウザスモークテスト |
| エージェントワークフロー | 期待されるルーティングを検証するフィクスチャログまたはテストデータ |
| 調査 / コンテンツ | 中立的な調査ブリーフ、主張のチェックリスト、公開可能なアウトライン |
| システム統合 | ドライランコマンド、設定バリデーション、シークレット漏洩スキャン |

別のチームメンバーがその評価を再実行できる状態になるまで、動的ワークフローが「再利用可能である」と主張してはなりません。

## アンチパターン

- 実際の判断ロジックをオペレーターから見えない場所に隠したスクリプトを生成すること。
- 動的ワークフローモードを「テストをスキップして良い免罪符」として扱うこと。
- 共通スキルやステータス成果物が求められているのに、使い捨てのドキュメントでお茶を濁すこと。
- 所有権、マージゲート、競合防止ポリシーのないまま複数エージェントを走らせること。
- 機密の調査データが生のまま公開ドキュメントに漏洩すること。

## 出力基準（Output Standard）

完了時に以下を提示します：

- ハーネスまたはスキルのパス
- 評価（Eval）の実行コマンドと結果
- コントロールパネルまたはハンドオフ成果物のパス
- 次に共通スキルとして抽出を検討すべき候補
