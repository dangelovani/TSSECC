# orch-refine-code

アクター・アクション・ターゲット: **orch · refine · code**。[`orch-pipeline`](../orch-pipeline/SKILL.md) 内の共通エンジンに対する軽量ラッパーです。

## 使用するタイミング

- 振る舞いは同一のまま**構造を改善**したい場合：モジュールの抽出、重複の排除、デッドコードの削除、ネストの低減、明瞭化のためのリネーム。
- 他の関連スキルとの区別：振る舞いの変更を伴う場合は本スキルの対象外です（`orch-change-feature` や `orch-fix-defect` を使用してください）。

## 運用設定

- **デフォルトの規模基準:** standard — 構造の再構築は複数ファイルに影響を及ぼします。
- **フェーズマスク:** 0 → 2（再構築の計画）→ 4（グリーンの維持）→ 5 → 6。新しい振る舞いテストは作成しません。既存のテストスイートが安全ネットとなります。
- **最初のステップ（フェーズ4）:** コードに触れる**前に**、関連するテストが存在し**グリーンであること**を確認します。カバレッジが不十分な場合は、まず仕様確定（characterization）テストを追加します。その後、小さなステップで構造を変更し、各ステップごとにテストを再実行します。

## 動作の流れ

1. 上記の設定で `orch-pipeline` エンジンを実行します。
2. デッドコードや重複の走査には、`refactor-cleaner` エージェントに委譲します（knip、depcheck、ts-prune を実行して安全に削除します）。
3. **Gate 1**（再構築計画）および **Gate 2**（コミット前）で停止して承認を求めます。
4. `refactor:` としてコミットします。差分は振る舞いに対して完全にニュートラルでなければなりません。

## 実行例

```
orch-refine-code: poller.py から NWS HTTP クライアントを抽出
→ テストがグリーンであることを確認 → 抽出計画の策定 [GATE 1: 承認]
→ 小さなステップで移動、常にテストをグリーンに維持 → コードレビュー
→ refactor: としてコミット [GATE 2: 確認]
```
