# Taste Distillation（テイストの蒸留）

このスタンドアロンスキルは `scripts/` に実装を含んでいます。後続の生成またはローカル撮影素材の編集には `taste-application` を使用します。指定された各ジャンルは固有のスタイルパックに保持してください。Flash Ethereal の測定値を Fluid Sketch や 3D Cyber Glitch に流用してはなりません。測定されたゼロは有効なデータであり、未入力フィールドと区別してください。

ローカル依存関係は `scripts/requirements.txt` に記載されています。個別に認可されたプロバイダー連携作業には `scripts/requirements-live.txt`、認証情報、および明示的な `TASTE_FORGE_ALLOW_LIVE=1` も必要です。`--dry-run` は認証情報を読み取らず、ジョブも送信しません。ローカルのエンドポイント名からワークフローが保存されたと推測してはならず、プロバイダー側の実際のワークフローまたはエビデンスを確認してください。

リファレンス動画を**スタイルパック（style pack）**に変換します: 後続のステージが決定的（deterministic）に消費できる測定値とアセットのフォルダです。

## 有効化のタイミング

- 「これらのクリップのルックを抽出してほしい」/「雰囲気を蒸留したい」/「再現性を持たせたい」
- ユーザーがリファレンス映像を持っており、LUT、カラーグレーディング、または一致するテンポ・リズムを求めているとき
- ジャンル別に整理されたルックのライブラリを構築するとき
- そのままでは「プロンプトでスタイルを言葉で指示する」ことになってしまうすべての要求

## コアとなる発見

**プロンプトでカラーグレーディングを指示することはできない。測定なら可能である。**

実際の映像での測定結果: カラー指示を強化しながら3回の有料生成を行ったところ、ミッドトーンの a\* は目標 **+24.9** に対して +1.9 → +2.8 → +0.3 と推移し、コントラストは目標 **34.7** に対して約19から全く動きませんでした。一方、同じ映像に測定済みパックを適用したところ、たった1回の決定論的処理（コストゼロ）でクロマMAE **1.88**、コントラスト **33.7** を達成しました。

役割分担は明確です: **モデルはコンテンツ、モーション、およびライティング構造を提供し、スタイルパックがルック（色味・質感）を提供する。** 生成プロンプトに色に関する単語を含めることは無駄であるどころか有害です — コストがかかる上に、LUTが求めるニュートラルなベースからレンダリングを遠ざけてしまいます。プロンプトには明示的に次のように指示してください: *「Colour: none. Render neutral. Grading is applied afterwards.（色: なし。ニュートラルにレンダリングすること。グレーディングは後から適用される）」*

## スタイルパックの内容

```
stylepacks/<genre>/
  grade.json      測定された色彩統計（後述）
  cadence.json    検出された全ショット境界 ＋ 導出された分布
  look.cube       33^3 LUT。DaVinci Resolve等のノードLUTとして直接ドラッグ可能
  spec.json       測定値にグラウンディング（根拠付け）されたVLM説明文
  grounding.txt   VLMに提供された測定事実
  stills/         最も長いショットからのフル解像度フレーム（条件付け画像）
  plates/         黒背景に抽出されたスクリーン合成用オーバーレイ要素
  props/          生成されたGLBメッシュ
  pack.json       マニフェスト（構成情報）
```

## 実行方法

```bash
python mint.py --genre <name> --refs a.mov b.mov c.mov     # オフライン、APIキー不要
python distill.py --genre <name>                            # VLM呼び出し1回
```

`mint.py` は純粋な数値解析です — ネットワーク通信なし、APIキー不要、決定論的であるため、パックをバックアップする代わりにいつでも再生成できます。

## 重要な測定項目

### 輝度ゾーンごとの彩度（Chroma）（全体一括ではなく）

色彩のアイデンティティは通常、**特定の輝度帯**に宿ります。全体的な a\*/b\* のオフセットでは、明部と暗部の色分け（スプリットトーニング）を数学的に表現できません。輝度ゾーン（`L* edges [0,15,35,55,75,100]`）ごとに彩度を測定します。

実例: L\*25 でバイオレット（a\* +24.9, b\* −17.5）、両端（明部・暗部）はほぼニュートラル。最暗部と最明部のみを報告すると「全体的な色かぶり」と誤認されます — **常に曲線全体を出力してください。**

### 中央値 ＋ MAD（中央絶対偏差）を使用（平均 ＋ 標準偏差は禁止）

実際のリファレンス素材における彩度は強い右歪み（偏り）を示します。ある測定リールでは、彩度の中央値が 17.5 であるのに対し平均値は 36.9 でした。平均値ベースのLUTを作成すると、素材が求める強さの約3倍も色を過剰に押し出してしまうことになります。

### コントラストは std(L\*)（白引く黒ではない）

実写映像では白引く黒のレンジはほぼ常に約100であり、何の判別材料にもなりません。

### 背景シェアは第一級の統計量

L\*10 未満のピクセルの割合を記録します。分布のモーメント（平均や分散）だけではこれを見落とします: クリップが適切な平均、標準偏差、彩度を保っていても、黒が浮いてグレーになっている場合があります。これにより、フレーム全体が濁った紫色の破綻状態であるにもかかわらず、MAE 1.88 / コントラスト 33.7 という合格スコアが出てしまった事例があります。

### 測定前にUIインターフェースをマスクする

画面録画されたリファレンスには、レターボックスの黒帯、ステータスバー、いいねアイコン、字幕テキストなどの静止したUI要素が含まれています。これらはルックの一部として統計に混入してしまいます: 黒帯はシャドウの重みを過大評価させ、赤いハートアイコンは a\* をマゼンタ方向に歪めます。**時間的分散（Temporal variance）によってこれらを綺麗に分離できます** — 映像は動きますがUIは静止しています — そのため手作業でのクロップ調整は不要です。実際の素材では約65%のピクセルが保持されます。

### カット周期（Cadence）には適応型しきい値が必要

適切なカット検出のしきい値は素材に依存します: ハイコントラストなアクション映像は30でも十分にカットを検出できますが、ダークで静かな映像ではカットが埋もれてしまいます。降順にしきい値をスイープし、最も高感度な設定で見つかったショットの90%以上を検出できる**最も高いしきい値**を採用します — これによりノイズよりも本物のカットを優先できます。非現実的なカット頻度（100カット/分 超）を示すしきい値は除外します（連続的なカメラのパンやチルトで毎フレーム誤検出するため）。

共有の `StatsManager` を使用して、**1回のデコードパス**でスイープ全体を実行します。しきい値ごとに再デコードする素朴な実装では、60fps素材で数秒と数分の差が生じます。

## オーバーレイプレート: スクリーンショットではなくアセット

スティル（静止画）はフレーム全体です — 合成すると単にもう1枚の絵が上に重なるだけです。**プレート**とは、リファレンスのグラフィック言語（フレア、光条、グリッチ破片など）を黒背景の上に抽出したものであり、キーイングなしでスクリーン描画モードでブレンドできるようにしたものです。

実素材で遭遇した2つの罠:

1. **絶対値なしきい値は破綻する。** 明るいリファレンスで `L>55 AND chroma>12` の選択を行うとフレームの約90%が選択され、「プレート」が人物の顔を含むただの写真になってしまいます。**パーセンタイル**（上位約3%）で選択し、**フレームの約22%以上を占めるプレートは破棄**します。
2. **明るさではなく分離度でランク付けする。** 「明るく鮮やかなピクセルの割合」で評価すると、全体が白飛びしたフレームが上位になり、黒背景に強烈なフレアが1本走る決定的なフレームが下位になってしまいます。スコアには `p99.5(energy) / median(energy)` を使用します。

また、採点前にマスク処理を行ってください: 焼き付けられたタイポグラフィは明るく鮮やかで高コントラストなため、マスクなしでは他人のタイトルカードの綺麗なプレートが生成されてしまいます。

## VLM（画像認識言語モデル）のグラウンディング

説明を求める前に、測定結果をシステムプロンプトに入力します。測定値を与えない場合、VLMは a\* +24.9 の色かぶりがある映像に対しても「目立ったカラーグレーディングはなく、ニュートラル」と誤認してしまいます。測定値を与えると、色かぶりを正確に説明し、セカンダリのアクセントカラーを独自に推論します。

曖昧な言葉（`varied`, `mixed`, `dynamic`, `some`, `often`, `neutral`, `or`）を禁止します — モデルは「多様なライティング」をレンダリングできません。**プロンプトだけでなくコード上で禁止を強制してください:** 約3回に1回はこの禁止が破られます。フィールドごとに再試行し、N回試行した後は失敗させるのではなく最も曖昧さの少ない回答を採用します。

ユーザーに伝えておくべき注意点: 仕様が測定値にグラウンディングされた時点で、その記述はもはや測定値に対する独立した検証手段ではなくなります。

## LUTベイクの落とし穴

- LUTは**ピクセルごとのRGB関数**しかエンコードできません。分布に依存するもの（ヒストグラムマッチング、パーセンタイルアンカーなど）は、ベイクする*前*に定数に縮約しなければなりません。さもないと、映像ではなく均一なLUTグリッドを測定してしまいます。
- `cv2.cvtColor(LAB2RGB)` は**内部でクランプ**するため、これを用いた色域外（OOG）テストは0%を返してしまいます。LabからリニアsRGBへの変換は自前で行ってください（実測で83.3%が色域外だった例があります）。
- アフィン変換ではなくオフセットによるクロマ転送を使用します。アフィン変換はソースのσで除算するためオーバーシュートを引き起こします — 実素材では b\* が目標 −17.5 に対して +11.6 に反転しました。オフセット方式によりMAEは 6.23 から 2.13 へ改善しました。
- ガマット圧縮は、MAEが同一であるにもかかわらず実行時間が3.8倍かかりました。オプトイン設定にしてください。

## アンチパターン

| やってはいけないこと | 理由 |
|---|---|
| 合成テスト映像に合わせて調整する | あるプロジェクトで4つの誤った結論を導く原因になりました。実映像ではそれらすべてが覆されました |
| MAEの数値だけを信頼する | 目視で明らかに破綻しているフレームでもMAE 1.88と良好に出てしまうことがあります |
| 彩度に平均値/標準偏差を使用する | 右に歪んだ分布のため、約3倍も過剰に色を強調してしまいます |
| 両端のゾーン（明部・暗部）のみを比較する | 構造上、両端はほぼニュートラルになります |
| ルックを文章で説明して完了とする | 仕様書はコンテンツと構造のためのものであり、色味はパックが担います |

## ハンドオフ（引き継ぎ）

スタイルパックがインターフェースとなります。パックが完成したら、**taste-application** スキルを使用してパックに合わせた生成・編集を行うか、またはカラリストに `look.cube` を直接渡してください。

## バンドルされているコード

本スキルの `scripts/` には疑似コードではなく動作する実装が含まれています。プロジェクト固有の前提はありません: 任意のリファレンス動画を指定すればスタイルパックが生成されます。

```bash
pip install -r scripts/requirements.txt
export FAL_KEY=...            # fal を呼び出すステージでのみ必要
```

すべてのネットワーク呼び出しは `TASTE_FORGE_DRY_RUN=1` または `--dry-run` でスタブ化できるため、費用をかけずに計画、プロンプト、トラックレイアウト、およびマニフェストを検査できます。
